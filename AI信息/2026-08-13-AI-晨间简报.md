## 重点新闻

### 1. GitHub Copilot 支持 Agent Plugins 1.0，Agent 插件走向跨工具标准化
**发布时间：2026-08-12**  
GitHub 宣布 Agent Plugins 1.0 已在 VS Code、Copilot CLI、GitHub Copilot SDK 和 Copilot app 中可用。该标准把 agent skills 与 MCP server 配置打包进一个可安装插件，AWS、Anysphere、Microsoft、OpenAI、Vercel 参与发布，Google 也加入核心维护。

**为什么重要：**  
这会降低为不同 AI 编程工具重复维护插件、MCP 配置和技能包的成本。对开发者和创业者来说，未来可以围绕“Agent 插件市场”做工具分发，而不是只绑定某一个模型或 IDE。

**来源：** [GitHub Changelog](https://github.blog/changelog/2026-08-12-agent-plugins-1-0-in-vs-code-copilot-cli-and-the-copilot-app/)

### 2. OpenAI 更新 ChatGPT Business / Enterprise 计费卡，Agent 与深度研究价格更清晰
**发布时间：页面显示 2026-08-13 更新**  
OpenAI 的 ChatGPT Rate Card 显示：GPT-5.6 Sol 每条消息约 10 credits，GPT-5.6 Sol Pro 为 50 credits；Agent mode 为 30 credits / message，Deep research 为 50 credits / task，Images 为 5 credits / generation，Voice 为 5 credits / minute。自动推理开启时，即使仍选择 Instant，也可能按 10 credits 计费。

**为什么重要：**  
企业用户不能再只看订阅费，需要按“Agent 调用、深度研究、Office/Workspace Agent token 消耗”核算真实成本。对开发者来说，产品设计要加入预算上限、任务复杂度分级、模型路由和缓存策略。

**来源：** [OpenAI Help Center：ChatGPT Rate Card](https://help.openai.com/en/articles/11481834)

### 3. GitHub Copilot 企业治理能力继续增强：插件、MCP、市场源可统一管控
**发布时间：2026-08-12**  
随着 Agent Plugins 1.0 可用，GitHub 同时强调企业可用现有 managed settings 管理插件：包括启用 / 禁用插件、添加可用 marketplace、限制安装来源，并可配合 MCP allowlists 控制 MCP server。

**为什么重要：**  
Agent 插件能接触代码、终端、内部工具和生产系统，企业落地时真正的难点不是“能不能用”，而是“谁能装、能连哪里、能执行什么”。这类治理能力会成为 AI 编程工具进入大公司的门槛。

**来源：** [GitHub Changelog](https://github.blog/changelog/2026-08-12-agent-plugins-1-0-in-vs-code-copilot-cli-and-the-copilot-app/)

## 值得关注的产品 / 工具

### Agent Plugins 1.0
适合：AI 工具开发者、MCP server 作者、企业平台团队。  
能做什么：把 agent skill、MCP server、工具配置打包成跨客户端插件。  
是否值得尝试：值得。尤其适合把内部 runbook、部署工具、数据查询工具封装给多个 agent 使用。

### GitHub Copilot Plugin / MCP 企业管控
适合：企业 DevTools、平台工程、安全团队。  
能做什么：限制插件来源、自动安装或屏蔽插件、配合 MCP allowlist 控制 agent 可访问的工具。  
是否值得尝试：企业强烈建议评估。Agent 权限治理会直接影响安全与合规。

### OpenAI ChatGPT Business / Enterprise credits 计费
适合：使用 ChatGPT Work、Agent mode、Deep research、Excel / PowerPoint 插件的团队。  
能做什么：按消息、任务、token 和功能核算 AI 使用成本。  
是否值得尝试：已经在用的团队应立刻复核预算，尤其是 Agent mode 和 Workspace Agent。

### Copilot + Ollama for JetBrains
适合：JetBrains 用户、本地模型用户、重视数据边界的团队。  
能做什么：在 JetBrains Copilot 中接入 Ollama 作为 BYOK provider，并结合跨会话 memory。  
是否值得尝试：值得试，但要注意本地模型质量、上下文能力和企业策略是否匹配。

### MAI-Code-1.1-Flash in GitHub Copilot
适合：追求低成本、低延迟代码辅助的 Copilot 用户。  
能做什么：Microsoft 新一代小型代码模型，支持视觉理解，并改进代码质量、指令遵循、工具使用和性能。  
是否值得尝试：可以作为低成本 coding model 试用；复杂任务仍建议和更强模型对比。

## 对我的启发

1. **开发者：把 Agent 能力做成可迁移插件。**  
   如果你有内部工具、部署流程、数据查询脚本，优先考虑封装为 skill + MCP server + plugin，而不是只写某个 IDE 的私有扩展。

2. **个人效率：开始记录不同 AI 功能的真实成本。**  
   Agent mode、Deep research、自动推理、Office 插件不再是“随便用”的功能。高频任务应优先用低成本模型或模板化工作流。

3. **创业机会：Agent 插件市场会出现垂直机会。**  
   例如面向法务、财务、客服、运维、安全审计的“可治理 Agent 插件包”，比单纯套壳聊天机器人更有企业价值。

4. **企业落地：先做权限和审计，再扩大 Agent 自动化。**  
   MCP server allowlist、插件来源控制、预算上限、日志追踪会成为 AI 工具采购的核心评估项。

5. **AI 编程：模型选择正在分层。**  
   小模型负责快速补全、简单修改和本地任务；强模型负责架构、复杂调试、跨文件重构和高风险自动化。
