# 今日 AI 简报：2026-07-25

## 一句话总结
过去 24 小时的主线是“AI Agent 产品化”：OpenAI、xAI、Anthropic、Runway 都在把语音、工作流、工具连接和多 Agent 编排做成日常工作入口。另一条主线是“成本与专用模型”：Microsoft、Google 都在用更便宜、更快的专用模型替代通用大模型，以支撑大规模生产场景。

## 重点新闻

### 1. OpenAI 将 ChatGPT Voice 接入桌面端 Work 与 Codex
- **发布时间**：2026-07-23，OpenAI Help Center 今日更新
- **摘要**：ChatGPT Voice 现在可在新版 ChatGPT 桌面 App 的 Work 和 Codex 中使用，用户可以用语音启动任务、打断对话、协调 Codex 或 Work 执行具备权限的操作。同一批更新还显示，ChatGPT Health 面向美国 18 岁以上用户推出，可连接健康记录与 Apple Health 数据。
- **为什么重要**：Codex/Work 正从“输入文字给 Agent”变成“用语音指挥多个工作流”。对开发者来说，桌面端 Codex 更接近常驻的工程助理；对普通用户来说，健康数据接入意味着 ChatGPT 继续向高敏感个人数据场景扩张。
- **来源链接**：[OpenAI ChatGPT Release Notes](https://help.openai.com/en/articles/6825453-chatgpt-release-notes)

### 2. Microsoft 发布 MAI-Image-2.5-Pro 与 MAI-Voice-2-Flash，继续降低对第三方模型依赖
- **发布时间**：2026-07-23
- **摘要**：Microsoft AI 推出两个自研模型公开预览：MAI-Image-2.5-Pro 面向高质量图像生成、编辑与图中文字渲染；MAI-Voice-2-Flash 面向高吞吐低延迟语音场景。官方称 MAI-Voice-2-Flash 比 MAI-Voice-2 快 2 倍、便宜 32%，价格为每 100 万字符 15 美元；MAI-Image-2.5-Pro 图像输出价格为每 100 万 image output tokens 106 美元。
- **为什么重要**：Microsoft 正把 Bing、PowerPoint、OneDrive、Dynamics 365、Azure 等产品逐步迁移到自研 MAI 模型。对开发者和企业采购者来说，这意味着 Azure Foundry 里的模型选择会更偏“任务专用、成本可控”，而不是只追最大模型。
- **来源链接**：[Microsoft AI 官方发布](https://microsoft.ai/?post_type=new)

### 3. xAI 推出 Grok Build Workflows：一次任务可扇出上百个并行 Agent
- **发布时间**：2026-07-23
- **摘要**：Grok Build 新增 Workflows，可把复杂任务拆成多阶段脚本，在后台扇出多个 Agent 并行执行、验证结果并汇总报告。官方示例包括大型 PR 审查、批量 issue triage、代码库安全审计；普通运行预算为 128 个 Agent，大任务最高 1,024 个。
- **为什么重要**：这把“多 Agent 编排”推向开发工具的一线界面。对工程团队来说，代码审查、迁移、审计、批量调研这类可并行任务，会从一次聊天变成可复用的 slash command。
- **来源链接**：[xAI Workflows in Grok Build](https://x.ai/news/workflows)

### 4. Google 发布 Gemini 3.5 Flash Cyber，面向防御方的专用安全模型
- **发布时间**：2026-07-21，过去 24 小时仍在官方新闻流重点展示
- **摘要**：Google DeepMind 推出 Gemini 3.5 Flash Cyber，基于 3.5 Flash 微调，用于发现、验证和修补漏洞。该模型将通过 CodeMender 以有限访问试点提供给政府和可信伙伴。Google 称它适合频繁扫描大型代码库，并在 V8 测试中发现 55 个独特确认问题，高于主线 3.5 Flash 和 Claude Opus 4.6 的对照结果。
- **为什么重要**：安全领域正在出现“低成本、高频、多调用”的专用模型路线，而不是每次都调用最贵的旗舰模型。对企业安全团队和 DevSecOps 工具创业者，这是一个明确方向：把模型能力嵌入 commit scan、CI、漏洞验证和补丁生成。
- **来源链接**：[Google DeepMind 发布](https://deepmind.google/blog/introducing-gemini-3-5-flash-cyber/)

### 5. Google Gemini 3.6 Flash 与 3.5 Flash-Lite 已面向开发者开放
- **发布时间**：2026-07-21，过去 24 小时继续发酵
- **摘要**：Gemini 3.6 Flash 面向生产级 Agent，主打更低延迟、更高 token 效率、更强代码和知识工作能力，价格为每 100 万输入 token 1.50 美元、输出 token 7.50 美元。Gemini 3.5 Flash-Lite 主打高吞吐低成本，官方称速度可达 350 output tokens/s，价格为每 100 万输入 token 0.30 美元、输出 token 2.50 美元。
- **为什么重要**：Google 明确把 Flash 系列定位为规模化 Agent 的默认选择。开发者如果在做搜索、文档处理、数据抽取、客服 Agent，应优先评估 3.5 Flash-Lite；需要更强工具使用、代码迁移、电脑操作的任务，可测试 3.6 Flash。
- **来源链接**：[Google 官方博客](https://blog.google/innovation-and-ai/models-and-research/gemini-models/gemini-3-6-flash-3-5-flash-lite-3-5-flash-cyber/)

### 6. Runway 推出 Media Router，自动为图像、视频、音频请求选择模型
- **发布时间**：2026-07-23
- **摘要**：Runway 在 Runway Dev 中发布 Media Router，可根据成本、质量、延迟、价格上限、允许/拒绝模型列表等配置，为视频、图像、音频生成请求自动选择模型。它会返回具体使用的模型及选择原因，并支持 dry-run 预检。
- **为什么重要**：生成式媒体模型更新太快，手动选模型会拖累成本和质量。Media Router 类似 LLM router，但面向视频、图像、音频工作流，适合内容平台、广告工具、创意 API、自动化视频生成产品。
- **来源链接**：[Runway Media Router](https://runway.com/news/company-news/introducing-runway-media-router)

### 7. Anthropic 更新 Claude Managed Agents API，增强企业 Agent 生命周期管理
- **发布时间**：2026-07-22，官方文档近 24 小时仍有更新
- **摘要**：Claude Platform release notes 显示，Claude Managed Agents 新增 `effort` 配置、环境与 memory store 生命周期 webhooks、创建 session 时可传入初始事件、thread 级事件流支持 delta 预览等。
- **为什么重要**：这不是模型发布，但对构建企业 Agent 很关键。Anthropic 正在补齐“托管 Agent 平台”的工程能力：状态、记忆、事件、部署生命周期、流式观察。这些能力决定 Agent 能否进入生产系统。
- **来源链接**：[Claude Platform Release Notes](https://platform.claude.com/docs/en/release-notes/overview)

### 8. Zenity 披露 ChatGPT Workspace Agents 漏洞 AgentForger
- **发布时间**：2026-07-23
- **摘要**：Zenity Labs 披露 AgentForger 漏洞：攻击者可通过特制 ChatGPT 链接，诱导用户点击后在组织内创建、授权并部署攻击者控制的 AI Agent。Zenity 称 OpenAI 已修复该问题。
- **为什么重要**：Agent 的安全边界不同于传统 SaaS。一个被诱导创建的 Agent 可能继承员工身份、连接器权限和组织上下文，风险高于单次 prompt injection。企业启用 Agent Builder、Workspace Agents 时，需要审批流、权限最小化、审计和异常 Agent 检测。
- **来源链接**：[Zenity Labs 披露](https://zenity.io/company-overview/newsroom/company-news/zenity-labs-uncovers-agentforger-a-chatgpt-vulnerability)

## 技术与论文

### PhantomFill：结构化表单会诱导模型“硬编答案”
- **发布时间**：arXiv 2026-06-11，今日被多家 AI 简报重新讨论
- **核心价值**：论文研究了一个很实际的问题：当你要求模型必须填 JSON、表格或固定字段时，即使原文没有答案，模型也更容易编造一个看似合规的值。换句话说，“格式约束”可能提高机器可读性，却降低诚实表达“不知道”的概率。
- **对非专业人士的解释**：如果你问模型“这段客服记录有没有投诉？”并强制它输出 `{complaint: true/false}`，模型可能为了填满字段而猜一个；如果允许它输出“信息不足”，结果会更可靠。
- **实际影响**：做 RAG、客服质检、合同抽取、医疗/金融表单自动化时，不要只用必填字段。应加入 `unknown` / `not_found` / `insufficient_evidence`，并要求引用证据片段。
- **来源链接**：[PhantomFill: When the Form Demands an Answer, Language Models Invent One](https://arxiv.org/abs/2607.20492)

## 对我的启发

1. **开发者**：Agent 产品的核心竞争点正在从“模型能力”转向“编排、权限、记忆、审计、成本路由”。如果你在做 AI 应用，优先补齐任务状态、工具权限、日志、失败恢复，而不是只换更强模型。

2. **个人效率**：语音 + 桌面 Agent 值得重新尝试。把“打开项目、审 PR、整理会议、查资料、生成文档”这类任务交给 Work/Codex/Grok Build，比单纯聊天更接近真实生产力。

3. **创业机会**：企业会需要 Agent 安全层。AgentForger 说明，新一代风险不是“模型说错话”，而是“Agent 带着员工权限做错事”。权限审计、Agent 行为检测、连接器安全、审批流会成为刚需。

4. **成本优化**：不要默认用旗舰模型。Google Flash-Lite、Gemini 3.6 Flash、Microsoft MAI-Voice-2-Flash 都说明，大规模 AI 产品要按任务拆模型：便宜模型跑批量，高阶模型做裁决或复杂推理。

5. **产品设计**：结构化输出要允许“不知道”。今天的 PhantomFill 讨论提醒：只追 JSON 合规会制造隐性幻觉。产品层面应把“证据不足”设计成一等结果。
